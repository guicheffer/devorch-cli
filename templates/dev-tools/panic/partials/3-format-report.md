## Step 3: Format Panic Report

Compile all gathered context into a well-structured markdown document suitable for a GitHub issue.

### Report Structure

Use the following template, populated with data gathered in Step 2:

```markdown

> **Generated by /panic command**
> Repository: [owner/repo]
> Branch: [branch-name]
> Date: [YYYY-MM-DD HH:MM:SS]

---

[Brief 1-2 paragraph description of the situation from Step 2.A]

[What the user was trying to accomplish from Step 2.A]

[Detailed explanation of current state]
```

### Validation Checks

Before proceeding, validate the report:

1. **Completeness**: Ensure all sections are populated
2. **Formatting**: Verify markdown syntax is correct
3. **Size**: Check total character count (GitHub issues have limits)
4. **Sensitive Data**: Scan for and redact:
   - API keys or tokens
   - Passwords or credentials
   - Personal information
   - Internal URLs or endpoints

**If report exceeds ~65,000 characters:**
- Truncate file contents to excerpts only
- Compress command history to summaries
- Move full content to local file reference

**If sensitive data detected:**
- Redact automatically where possible
- Warn user about remaining sensitive data
- Ask for confirmation before proceeding
