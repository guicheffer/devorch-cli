# 7. Scope

**Cycle:** MAKE (1 Sprint)
**Phase:** Planning

## Purpose

Define clear boundaries for the sprint. Determine what's in scope and what's out of scope for this iteration to ensure focused, shippable work.

## AI-Native Approach

Use AI to:
- Break down validated hypotheses into sprint-sized work
- Identify dependencies and risks
- Estimate complexity and effort
- Generate scope documentation

## Key Activities

- Define sprint goals
- Break down work into tasks
- Identify what's in/out of scope
- Assess dependencies
- Set success criteria

## Inputs

- Prioritized opportunity from backlog
- Validated hypothesis
- Technical constraints
- Sprint capacity

## Outputs

- **Sprint scope**: What we're building
- **Out of scope**: What we're NOT building (yet)
- **Success criteria**: How we'll know we're done
- **Risks and dependencies**: What could block us

## Common Pitfalls

- Scope creep during the sprint
- Underestimating complexity
- Not defining "done" clearly
- Including too much in one sprint
- Not considering dependencies

## Success Criteria

- [ ] Sprint goal is clear and achievable
- [ ] Scope is realistic for one sprint
- [ ] In/out of scope is documented
- [ ] Dependencies are identified
- [ ] Success criteria are measurable
