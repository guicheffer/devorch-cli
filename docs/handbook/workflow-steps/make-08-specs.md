# 8. Specs

**Cycle:** MAKE (1 Sprint)
**Phase:** Planning

## Purpose

Create clear, context-rich specifications that serve as the source of truth for Product, UX, and Engineering. Specs are written in markdown and optimized for AI collaboration.

## AI-Native Approach

Use AI to:
- Generate initial spec drafts
- Ensure completeness and clarity
- Validate technical feasibility
- Create consistent documentation

## Key Activities

- Write Product Spec (PRD)
- Write UX Spec
- Write Engineering Spec
- Align all three specs
- Review and refine

## Inputs

- Sprint scope
- Validated hypothesis
- Research insights
- Technical constraints
- Design principles

## Outputs

- **Product Spec (prd.md)**: What and why
- **UX Spec (ux-spec.md)**: User experience and flow
- **Engineering Spec (eng-spec.md)**: How to build it
- **Aligned understanding**: All three specs tell the same story

## Common Pitfalls

- Specs that are too vague or too detailed
- Misalignment between Product/UX/Engineering
- Writing for humans only (not AI-optimized)
- Not including enough context
- Specs that become stale quickly

## Success Criteria

- [ ] All three specs are complete and aligned
- [ ] Context is clear and comprehensive
- [ ] Technical approach is validated
- [ ] User flows are documented
- [ ] Specs are AI-optimized (markdown, clear structure)
