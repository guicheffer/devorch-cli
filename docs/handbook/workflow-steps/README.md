# Think vs Make Cycle: Workflow Steps

This guide breaks down each step of the AI-Native dual-track process, providing tools and guidance for being successful at every stage.

![Think vs Make Cycle](../images/blueprint-think-make-cycle.png)

## How to Use This Guide

Each workflow step includes:
- **Purpose**: What this step achieves
- **AI-Native Approach**: How to leverage AI effectively
- **Key Activities**: What you do in this step
- **Inputs/Outputs**: What you need and what you produce
- **Tools & Techniques**: Specific methods (to be populated with examples)
- **Common Pitfalls**: What to avoid
- **Success Criteria**: How to know you're done


## 🟩 THINK Cycle (Non-Linear Discovery)

The THINK cycle is dedicated to discovering the right problem to solve. This is a non-linear process where you may loop through steps multiple times.

### 1. [Hypothesis](./think-01-hypothesis.md)
Define a clear, testable hypothesis about a customer problem or opportunity.

### 2. [(Deep) Research](./think-02-deep-research.md)
Gather and synthesize context to validate or refine the hypothesis.

### 3. [Brainstorm](./think-03-brainstorm.md)
Generate multiple potential solutions to the validated problem.

### 4. [Prototype](./think-04-prototype.md)
Create a functional prototype to visualize and test the solution.

### 5. [Validate](./think-05-validate.md)
Test the prototype with users and gather feedback.

### 6. [Update Hypothesis](./think-06-update-hypothesis.md)
Refine or pivot based on learnings; decide whether to iterate or proceed to MAKE.


## 🔄 CHECK (Bridge Between Cycles)

The CHECK phase connects THINK and MAKE, ensuring we prioritize correctly and capture learnings.

### [Prioritize](./check-prioritize.md)
Stack-rank validated hypotheses; determine what moves from THINK to MAKE.

### [Learn](./check-learn.md)
Capture learnings from both cycles to build organizational intelligence.


## 🔵 MAKE Cycle (1 Sprint Execution)

The MAKE cycle is focused on rapid execution and delivery. All steps happen within a single sprint (1 week).

### 7. [Scope](./make-07-scope.md)
Define clear boundaries for the sprint; what's in and out of scope.

### 8. [Specs](./make-08-specs.md)
Create context-rich specifications (PRD, UX Spec, Engineering Spec) that serve as the source of truth.

### 9. [Design](./make-09-design.md)
Create detailed design artifacts ready for development.

### 10. [Develop](./make-10-develop.md)
Build the solution using AI as a development partner.

### 11. [QA](./make-11-qa.md)
Verify implementation meets requirements and is production-ready.

### 12. [Demo](./make-12-demo.md)
Demonstrate progress daily to create tight feedback loops.

### 13. [Deploy](./make-13-deploy.md)
Ship to production and begin measuring actual outcomes.


## 🌊 The Continuous Flow

```
THINK → CHECK → MAKE → CHECK → THINK
  ↓       ↓       ↓       ↓       ↓
Building context throughout (.md feeding back to knowledge bases)
```

This is not a waterfall process. Context flows continuously:
- **THINK** validates problems and de-risks ideas
- **CHECK** ensures we prioritize and learn effectively
- **MAKE** delivers working software in production
- **Learnings** feed back into both cycles, making each iteration smarter


## Key Principles

### Demo Daily, Ship Weekly
- Daily demos create tight feedback loops
- Weekly deployments maintain momentum
- Continuous validation prevents costly mistakes

### Natural Language is the Source Code
- All specs written in markdown
- Optimized for AI collaboration
- Single source of truth across Product, UX, and Engineering

### Human-in-the-Loop, AI-in-the-Flow
- AI handles heavy lifting
- Humans provide judgment and creativity
- Pause for human input when needed

### Done Means Outcomes, Not Deployed
- Deployment is the beginning, not the end
- Measure actual impact on users and business
- Feed learnings back to CHECK cycle
