# 13. Deploy

**Cycle:** MAKE (1 Sprint)
**Phase:** Delivery

## Purpose

Ship working software to production every week. Deployment is not the end—it's the beginning of learning what actually happens when users interact with the feature.

## AI-Native Approach

Use AI to:
- Automate deployment processes
- Monitor deployment health
- Generate release notes
- Analyze post-deployment metrics
- Alert on issues

## Key Activities

- Deploy to production
- Monitor metrics and errors
- Validate in production
- Communicate release
- Measure impact

## Inputs

- QA-approved feature
- Demo feedback
- Deployment checklist
- Rollback plan

## Outputs

- **Live feature**: In production
- **Release notes**: What was shipped
- **Monitoring dashboard**: Key metrics
- **Impact baseline**: Pre-deployment metrics for comparison

## Common Pitfalls

- Deploying without monitoring in place
- No rollback plan
- Not communicating the release
- Treating deployment as "done"
- Not measuring actual impact

## Success Criteria

- [ ] Feature is live in production
- [ ] Monitoring is active
- [ ] Release is communicated
- [ ] Rollback plan is ready
- [ ] Baseline metrics are captured
- [ ] Ready to measure outcomes (not just outputs)

## After Deploy: Measure Outcomes

Remember: **Done means outcomes, not deployed.** After deploying, you must:
- Track how users interact with the feature
- Measure business metrics
- Compare to success criteria
- Feed learnings back to CHECK cycle
- Decide: iterate, scale, or sunset
