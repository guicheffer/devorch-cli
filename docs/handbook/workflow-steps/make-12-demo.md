# 12. Demo

**Cycle:** MAKE (1 Sprint)
**Phase:** Validation

## Purpose

Demonstrate tangible progress every day to create tight feedback loops. The daily demo validates we're building the right thing and catches issues early.

## AI-Native Approach

Use AI to:
- Prepare demo scripts
- Generate demo environments
- Create presentation materials
- Document feedback
- Synthesize stakeholder input

## Key Activities

- Prepare demo environment
- Walk through new functionality
- Gather feedback from stakeholders
- Document questions and concerns
- Adjust plans based on feedback

## Inputs

- Working feature (QA'd)
- Demo script
- Stakeholder list
- Feedback collection approach

## Outputs

- **Demo recording/notes**: What was shown
- **Stakeholder feedback**: What they said
- **Action items**: What needs to change
- **Go/no-go decision**: Ready to deploy or iterate

## Common Pitfalls

- Demoing unfinished or buggy features
- Not preparing the demo environment
- Defensive responses to feedback
- Not recording feedback properly
- Skipping demos when "nothing new" to show

## Success Criteria

- [ ] Feature is demo-ready
- [ ] Stakeholders have seen the work
- [ ] Feedback is collected and documented
- [ ] Clear decision on next steps
- [ ] Demo happens daily (not just end of sprint)
